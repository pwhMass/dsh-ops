# 紧凑文件范围

English: [Compact Native file ranges](native-ranges.md).

`ops_read_files` 完整返回所请求的范围时，每个文件仅显示一个路径标题、精确的行号正文，以及一条版本/续读提示。只有所有文件具有完全相同的绝对父目录时，才共享一条 JSON 引号包围的 `Base`；各文件名同样使用 JSON 引号，并相对于该目录解析。父目录不同则保留各自的绝对路径。

```text
[Base: "/workspace/src"]
=== FILE: "server.ts" (Lines 1-2 of 80) ===
1|import { createServer } from 'http';
2|const port = 8080;
[revision=cfd1bc81432fd6b88748b827f46bb4242db17cf8655cf4ea90f3ba0e62065355; more lines; nextOffset=3]
```

`N|`（单文件为 `N | `）之后是**原样源码**，保留缩进、引号和反斜杠，可直接把正文用于字面编辑。即使源码看起来像 JSON，也仍然是原文，不要自行解码。

含控制字符、DEL、NEL 或 Unicode 换行分隔符的行改为 `Nj|"..."` / `Nj | "..."`：可信行号栏里的 `j` 表示正文是带引号的**完整 JSON 字符串**，编辑前只解码一次；编辑 API 本身不会自动反转义。真实制表符因此显示为 `1j|"\t"`，反斜杠加字母 t 两个普通字符显示为原样 `1|\t`。第一条编码行之前会有一次编码说明。结构标记与正文共同构成可逆表示，源码不能伪造额外物理行或文件标题；LF/CRLF 规则仍由 worker 决定。

Grep 的完整路径字段使用 JSON 引号，格式为 `"path":Nj | "..."`；无行号时使用 `"path" [json] | "..."`，因此文件名中的 `:12j`、`[json]` 或分隔符不能冒充编码标记。声明类型移至源码正文之外，例如 `"path":Nj [function] | "..."`，编辑时不得把类型元数据复制进去。Diff 使用 `+ Nj | "..."` / `- Nj | "..."`。规范数据与 PTC 仍返回原始文本。显示预算或 worker 截断的行不能当作完整源码复制、解码，也不得猜测补齐 JSON，应按恢复提示继续读取。

`more lines` 表示文件尚未读到末尾，按 `nextOffset` 继续；`end of file; complete=true` 表示本范围已经到达文件末尾。汇总的 `requested ranges returned` 仅证明所请求的范围正文全部返回，不代表读取了所有完整文件。完整版本散列、总行数和每个文件的续读位置继续保留；字节大小及重复计数仍在规范数据和 PTC 返回值中。逐文件版本回执省去重复的 `Notice: ` 前缀与末尾句点；汇总 `Notice` 以及版本、续读和完整性事实均保留。

发生物理截断、缺失文件、覆盖事实异常、引用存储或其他不确定情况时，继续使用诊断输出并保留明确恢复提示。最终显示预算截断不会保留成功汇总，而会要求用更小上限重新读取原范围。上下文去重同时识别 `N|`、`Nj|`、`N | ` 与 `Nj | ` 格式；只有当前供应商上下文中存在完全相同的旧正文证据，才能返回未变化引用。
